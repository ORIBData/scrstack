# Engineering audit — 2026-11-12

Disposition: production sign-off withheld. This is a source review and focused
local verification of the implemented foundation, not certification of the PRD
or validation of deployed scanners. Live production stores were not modified
during this audit.

## Fixed findings

| Severity | Finding and correction |
| --- | --- |
| High | Successful discovery left vanished or inaccessible assets in scope. Reconciliation now withdraws eligibility inside the same transaction, restores it only for returned resources, and preserves asset history. Failed inventories do not withdraw eligibility. |
| High | Concurrent schema bootstrap could race on DDL. A PostgreSQL transaction advisory lock now serializes connection-table migrations. |
| High | Management handler construction allowed a missing token when called outside main. Routes now register only with a token of at least 32 characters. |

## Outstanding production risks

1. **High — legacy scanner trust boundary.** `/scanFile` and `/scanPath` accept
   host paths without authentication or a filesystem allow-list. Upload routes,
   metrics and version are also unauthenticated. Do not route this service
   through public Traefik. Kubernetes, nonroot Compose and alternate Dockerfiles
   require a dedicated deployment/security review before use.
2. **High — incomplete credential lifecycle.** REST supports create/list/get,
   test and discovery; scope edits, disable/delete and credential rotation are
   missing. Bootstrap bearer authentication has no managed token scopes,
   expiry, revocation store or distributed rate limits. Master-key rotation is
   not implemented. Losing that key makes stored credentials unusable.
3. **High — concurrent provider work is not bounded globally.** Authenticated
   callers can launch many synchronous tests/discoveries. Add bounded job
   admission, idempotency and durable worker claims before large deployments.
   Provider rate-limit backoff and circuit breaking are absent.
4. **Medium — stale check status.** Discovery compares connection state under
   row lock, but Test/failed-discovery status writes can still race with a
   credential replacement. Use an explicit configuration revision for all
   status writes; updated_at currently mixes configuration and check changes.
5. **Medium — performance.** Connection listing is unpaginated; asset listing
   has keyset pagination. Discovery performs one SQL round trip per asset in a
   transaction, which is costly against hosted PostgreSQL. Batch writes after
   measuring realistic inventory size. Readiness creates fresh clients/pools
   and holds a mutex during remote calls; reuse clients and coalesce probes.
6. **Medium — provider coverage.** A successful list may omit private resources
   without a policy error. Count-based testing does not prove complete scope or
   read-content permission. GitHub OAuth consent/refresh and GAR workload
   identity are absent. Generic OCI and GitLab adapters are not implemented.
7. **High — QA and supply-chain evidence incomplete.** No completed current
   dependency advisory scan, image CVE scan, image SBOM/signature verification,
   fault-injection run or VPS acceptance test. govulncheck and Trivy were not
   installed in the local command path. A clean vet result is not a CVE scan.
8. **High — product scope gap.** Fetching immutable snapshots/digests, safe
   unpacking, malware/SCA/SAST/DAST execution, assessments, findings, risk
   policies, remediation and durable scheduling are not implemented by the
   SCRS foundation. Asset discovery must not be advertised as protection or
   remediation. No autonomous source deletion or write-back is implemented.

## Endpoint and data review

`/system/healthz`, `/system/readyz`, `/docs` and Swagger assets are public.
`/connections`, connection lookup/actions and `/assets` require the bootstrap
bearer token. Create uses a bounded body and provider-field allow-lists;
credentials are encrypted separately from public JSONB. The server exposes no
REST deletion path. OpenAPI documents the implemented routes but provider
config schemas and response/error schemas remain too loose for contract-first
client generation.

Discovery and audit writes share a transaction. Existing connection replacement
is opt-in through environment seeding. Resource uniqueness is per connection;
future assessment dispatch must reject ambiguous matching connections. Missing
resources retain history with eligibility withdrawn after successful inventory.
Backups, restore drills, retention and key recovery remain operator obligations
without tested project workflows.

Local cleanup uses project labels/local repository names and SCRS tag prefixes
in shared Docker Hub repositories. It does not force image deletion and skips
container-used images. A race remains between inventory and deletion when other
processes retag images or create containers; run cleanup without concurrent
release activity. Remote registry images and storage volumes are not pruned.
Release preserves the local Docker endpoint but custom remote TLS contexts and
cloud Buildx builders are not fully supported by the temporary config approach.
